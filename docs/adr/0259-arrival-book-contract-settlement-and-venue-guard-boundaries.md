# ADR 0259 — 실제 도착 호가·계약 정산·거래소 대사·발산 감축의 경계를 검증한다

- **Status**: Proposed (2026-10-07, 항목별 구현·검증·창 발효 대기)
- **Related**: ADR 0017 · ADR 0151 · ADR 0175 · ADR 0183 · ADR 0254 · ADR 0257 · ADR 0260

## Context

유저의 2026-10-06 C3 계측 승인과 10-07 계약 종료를 모멘텀과 같게 처리하라는 재정을 따른다.
야간 C-b 의뢰는 네 경계를 지정했다. 결정 가격만으로 실제 제출 호가 비용은 알 수 없고, 정산된
계약의 가상 장부와 죽은 캐시를 계속 주문 근거로 쓰면 반복 거부와 무주인 반대 포지션이 생긴다.
침묵한 사용자 스트림은 거래소 체결·손절 발동을 놓칠 수 있어 독립 대사가 필요하다.

## Decision

1. 모멘텀의 기존 arrival_mid는 종가라는 해석을 유지한다. 제출 순간의 실제 스트리밍 북 중간가는
   별 필드와 가격 종류·시각으로 영속 주문과 체결 원장에 보존한다. 낡거나 없는 북은 None이며
   추정하지 않는다. 도착 호가 대비 비용은 기존 종가 비용과 따로 집계한다. 결정·주문 가격은 유지한다.
2. MR60·MR15·트렌드의 신규 진입 가능 시각은 모멘텀과 같은 명부·판정으로 결정한다.
   TRADING·onboard 이후·deliveryDate 30분 전까지이며 보유는 실제 정산까지 유지한다.
   정산 뒤에는 검증된 종료 Mark로 가상 장부를 닫고 죽은 MR 헤지 베타를 제거한다. Mark가 없으면
   정산 대사 대기로 남기고 반복 청산 주문은 멈춘다. 트렌드 재시작은 없는 계기를 예외로 열지 않는다.
   실제 잔량은 ADR 0254 보류와 사람 대사 대상이다. 새 명부 REST는 추가하지 않는다.
3. 8시간 위치 감사의 같은 작업 스레드에서 보유 종목의 열린 알고 주문과 보유·최근 거래 종목의
   userTrades를 캐시와 대조한다. 불완전·실패 조회는 통과가 아니며 해당 범위를 보류한다.
   감사당 종목 상한 50개, 종목별 알고 조회 1회(weight 1)·체결 조회 1회(weight 5)로 최대 100회다.
   기존 positionRisk(weight 5)를 합쳐 최대 weight 305이며 하루 세 감사 최대 915다.
   체결 1,000행에 닿으면 완결로 인정하지 않고 보류하며 상한 밖 종목을 조용히 누락하지 않는다.
   418/429는 즉시 중단하고 재시도하지 않는다. 검증되지 않은 순서를 추정하지 않는다.
   불일치 종목은 ASCII ERROR와 ADR 0254의 같은 보류 집합에 남긴다. schema 1의 행 모양과
   수량 뜻은 유지하고 사유는 기존 문자열 필드에 기록한다. 성공한 전체 대사만 해당 보류를 해제한다.
4. 발산 또는 읽기 실패로 보류된 종목의 감축은 reduce_only=True다. 캐시 넷의 상쇄·반대·부족을
   이유로 플래그를 내리지 않는다. 공통 어댑터가 의도상 감축을 받아 모멘텀 τ=0 MARKET에도 적용한다.
   거래소가 이미 flat이면 거부로 끝나므로 무주인 반대 자리를 열지 않는다. 정상 종목의 기존 넷팅
   판정과 증가 주문은 유지한다. 공유 종목의 수동 청산은 캐시 유령·다른 슬리브 보호에 영향을 준다.

## Consequences

좌표·배분·위험 한도와 정상 신호는 유지한다. 자료가 부족하면 위험을 새로 여는 대신 보류한다.
각 항목의 구현·검증 완료는 별도 증거이며 이 결정문만으로 완료를 주장하지 않는다.
운영 발효는 지정 창의 병합·배포·부팅 검증 뒤다.
